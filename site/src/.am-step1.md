## B 작업 순서

**시나리오:** SkillBoost 운영팀은 SSH를 열지 않고 쇼핑몰용 Kubernetes 기반을 준비합니다. 먼저 네트워크·통신 규칙·AWS 권한을 만든 뒤 서버를 시작합니다.

| 개념 | 이 실습에서 하는 일 | 혼동하지 말 것 |
| --- | --- | --- |
| VPC · 서브넷 | 노드 IP와 배치할 AZ를 정합니다 | Kubernetes Pod 네트워크와 다릅니다 |
| IGW · 라우팅 테이블 | 인터넷으로 나갈 경로를 제공합니다 | 퍼블릭 서브넷만으로 인터넷 접속이 되지는 않습니다 |
| 보안 그룹 | 노드 사이 통신과 외부 연결을 제어합니다 | 자기 참조는 인터넷 전체 허용이 아닙니다 |
| IAM 역할 | EC2의 SSM API 호출을 허용합니다 | 네트워크 포트를 여는 설정이 아닙니다 |

SSM 접속에는 **IAM 권한 + 실행 중인 에이전트 + HTTPS 아웃바운드 경로**가 함께 필요합니다. 이 실습은 퍼블릭 IP와 IGW를 사용합니다. 별도 VPC 엔드포인트는 만들지 않습니다.

**작업 위치:** `aws` 조회는 CloudShell, `apt`·`kubeadm`·`kubectl`은 EC2 노드 셸입니다. CloudShell에 접속했다고 노드 안으로 들어간 것은 아닙니다.

```flow TB
(시작) -> VPC 생성
VPC 생성 -> 보안 그룹
보안 그룹 -> IAM 역할
IAM 역할 -> cap-master 시작
cap-master 시작 -> (② 공통 기반 설치)
```

## C 사전 준비 — CloudShell

리전이 아시아 태평양(서울) ap-northeast-2인지 먼저 확인합니다. 콘솔 오른쪽 위 `>_` 아이콘으로 CloudShell을 엽니다.

! **주의:** `m7i-flex.large` 3대가 실행되는 동안 비용이 발생합니다. 이 클러스터는 7일차까지 사용하므로 삭제하지 말고, 수업 종료 시 인스턴스만 중지하세요.

**계정 확인:**

```bash
aws sts get-caller-identity --region ap-northeast-2
```

**명령어 해석:**

- `aws sts ...` — STS에 "지금 접속한 나는 누구인가"를 물어 자격 증명을 확인합니다.
- `--region` — 이 명령 하나에만 대상 리전을 지정합니다.

**예상 출력:** `Account`에 본인 계정 번호가 보이면 정상입니다.

**실습 변수 저장** — 세션이 끊겨도 홈 디렉터리 파일은 남습니다:

```bash
cat > ~/cap-k8s.env <<'EOF2'
export AWS_PAGER=""
export REGION=ap-northeast-2
export AZ=ap-northeast-2a
EOF2
source ~/cap-k8s.env
echo "$REGION / $AZ"
```

**명령어 해석:**

- `cat > 파일 <<'EOF2'` — EOF2 줄까지의 내용을 파일로 저장하는 히어독(heredoc)입니다.
- `export` — 이후 실행할 명령들이 참조하는 환경 변수를 만듭니다.
- `AWS_PAGER=""` — aws CLI가 자동으로 띄우는 페이징 뷰어를 끕니다.
- `source` — 파일을 **현재 셸에서** 실행해 변수를 즉시 적용합니다.

**예상 출력:** `ap-northeast-2 / ap-northeast-2a`

! **주의:** CloudShell은 20~30분 무입력 시 세션이 종료됩니다. 다시 열 때마다 `source ~/cap-k8s.env`를 먼저 실행하세요.

**인스턴스 유형 확인** — 2a에서 제공되는지 먼저 확인합니다:

```bash
aws ec2 describe-instance-type-offerings --location-type availability-zone \
  --filters Name=instance-type,Values=m7i-flex.large Name=location,Values=$AZ \
  --query 'InstanceTypeOfferings[].[InstanceType,Location]' --output text --region $REGION
```

**명령어 해석:**

- `describe-instance-type-offerings` — 리전이 판매하는 인스턴스 유형과 위치(AZ) 목록을 조회합니다.
- `--filters` — 유형이 m7i-flex.large이고 AZ가 2a인 결과로 줄입니다.
- `--query` · `--output text` — JMESPath 문법으로 필요한 필드만 텍스트로 뽑습니다.

**예상 출력:** `m7i-flex.large  ap-northeast-2a` — 출력이 비면 이후 모든 단계에서 `m5.large`를 사용하세요.

## D 태스크 1: VPC 생성

💭 같은 리전이라도 AZ마다 제공하는 인스턴스 유형이 다릅니다. 노드 3대는 2a에 두지만, 7일차 ALB가 서로 다른 AZ의 서브넷 2개를 요구하므로 2c 서브넷을 미리 만듭니다.

**콘솔:** 검색창에 `VPC` → VPC 서비스 → **VPC 생성**에서 아래 표대로 입력합니다.

| 항목 | 값 |
| --- | --- |
| 생성할 리소스 | VPC 등 |
| 이름 태그 자동 생성 | 체크 · cap |
| IPv4 CIDR 블록 | 10.20.0.0/16 |
| AZ 수 | 2 — 2a, 2c |
| 퍼블릭 서브넷 수 | 2 |
| 프라이빗 서브넷 수 | 0 |
| 서브넷 CIDR | 2a: 10.20.1.0/24 · 2c: 10.20.2.0/24 |
| NAT 게이트웨이 | 없음 |
| VPC 엔드포인트 | 없음 |
| DNS 옵션 | DNS 호스트 이름 · DNS 확인 모두 체크 |

! **주의:** NAT 게이트웨이는 시간당 요금이 발생합니다. 노드를 퍼블릭 서브넷에 두므로 NAT가 필요 없습니다.

미리 보기에 `cap-vpc`, 서브넷 2개, `cap-igw`가 보이면 **VPC 생성**을 클릭합니다.

**태그 추가:** Your VPCs에서 `cap-vpc` → 태그 탭 → 태그 관리 → `Project=capstone`, `Owner=cap` 추가.

! **주의:** 이 태그는 채점 · 정리 스크립트가 리소스를 찾는 기준입니다. 모든 리소스에 같은 태그를 붙입니다.

**확인 (CloudShell):** ID를 저장합니다.

```bash
source ~/cap-k8s.env
VPC_ID=$(aws ec2 describe-vpcs --filters Name=tag:Name,Values=cap-vpc \
  --query 'Vpcs[0].VpcId' --output text --region $REGION)
SUBNET_A=$(aws ec2 describe-subnets --filters Name=vpc-id,Values=$VPC_ID Name=availability-zone,Values=ap-northeast-2a \
  --query 'Subnets[0].SubnetId' --output text --region $REGION)
echo "export VPC_ID=$VPC_ID"     >> ~/cap-k8s.env
echo "export SUBNET_A=$SUBNET_A" >> ~/cap-k8s.env
```

**명령어 해석:**

- `describe-vpcs` · `describe-subnets` — 태그 이름이나 VPC ID, AZ로 리소스를 검색합니다.
- `$(...)` — 명령 치환입니다. 명령 출력을 그 자리에 넣어 변수에 저장합니다.
- `--query 'Vpcs[0].VpcId'` — 여러 결과 중 첫 번째의 VpcId만 추출합니다.
- `>>` — 파일 끝에 한 줄씩 추가합니다. 다음 세션에 `source`만 하면 변수를 다시 씁니다.

## E 태스크 2: 보안 그룹 생성

💭 노드 사이에는 6443, 10250, etcd, Calico VXLAN(UDP 4789) 등 여러 포트가 필요합니다. **같은 보안 그룹끼리 모든 트래픽을 허용하는 자기 참조 규칙 하나**로 처리하고, 인터넷 인바운드 규칙은 만들지 않습니다.

**콘솔:** EC2 → 보안 그룹 → 보안 그룹 생성에서 아래대로 입력하고, 인바운드 규칙 없이 생성합니다.

| 항목 | 값 |
| --- | --- |
| 보안 그룹 이름 | cap-k8s-node-sg |
| 설명 | cap k8s nodes |
| VPC | cap-vpc |
| 인바운드 규칙 | 없음 (다음에 추가) |
| 아웃바운드 규칙 | 기본값 (모든 트래픽 허용) |
| 태그 | Name=cap-k8s-node-sg · Project=capstone · Owner=cap |

! **주의:** 자기 참조 규칙은 생성 뒤에만 추가할 수 있습니다. 생성 화면에서는 자기 자신을 소스로 고를 수 없습니다.

**자기 참조 규칙 추가:** 생성된 `cap-k8s-node-sg` → 인바운드 규칙 탭 → 인바운드 규칙 편집 → 규칙 추가 → 유형 **모든 트래픽**, 소스 **사용자 지정**에서 `cap-k8s-node-sg`(자기 자신) 선택 → 규칙 저장.

**확인 (CloudShell):**

```bash
source ~/cap-k8s.env
SG_ID=$(aws ec2 describe-security-groups --filters Name=group-name,Values=cap-k8s-node-sg Name=vpc-id,Values=$VPC_ID \
  --query 'SecurityGroups[0].GroupId' --output text --region $REGION)
echo "export SG_ID=$SG_ID" >> ~/cap-k8s.env
```

**명령어 해석:**

- `describe-security-groups` — 그룹 이름과 VPC ID로 보안 그룹을 찾아 GroupId를 저장합니다.
- `SG_ID` — 이후 인스턴스 시작 화면에서 참조하는 대상 ID입니다.

**보안:** 인바운드에 `0.0.0.0/0`이 없으므로 인터넷에서 노드로 들어오는 연결은 모두 차단됩니다. Session Manager는 노드의 SSM 에이전트가 바깥으로 HTTPS 연결을 맺는 방식이라 인바운드 규칙이 필요 없습니다.

## F 태스크 3: IAM 역할 생성

💭 역할이 없으면 SSM 에이전트가 실행 중이어도 접속 수단이 없어집니다. 이 실습은 SSH도 쓰지 않습니다. 7일차에는 이 역할에 EBS CSI 드라이버용 정책을 추가합니다.

**콘솔:** 검색창에 `IAM` → 역할 → 역할 생성에서:

| 항목 | 값 |
| --- | --- |
| 신뢰할 수 있는 엔터티 | AWS 서비스 |
| 사용 사례 | EC2 (첫 번째 라디오 버튼) |
| 권한 정책 | AmazonSSMManagedInstanceCore |
| 역할 이름 | cap-k8s-node-role |
| 태그 | Project=capstone · Owner=cap |

**참고:** 콘솔에서 EC2용 역할을 만들면 같은 이름의 인스턴스 프로파일이 자동 생성됩니다. 시작 화면에서는 이 인스턴스 프로파일 이름을 선택합니다.

**확인 (CloudShell):**

```bash
aws iam get-instance-profile --instance-profile-name cap-k8s-node-role \
  --query 'InstanceProfile.Roles[].RoleName' --output text
aws iam list-attached-role-policies --role-name cap-k8s-node-role \
  --query 'AttachedPolicies[].PolicyName' --output text
```

**명령어 해석:**

- `get-instance-profile` — 역할과 같은 이름의 인스턴스 프로파일이 만들어졌는지 확인합니다.
- `list-attached-role-policies` — 역할에 붙은 관리형 정책을 나열합니다. 여기서는 `AmazonSSMManagedInstanceCore` 하나여야 합니다.

**예상 출력:** 두 줄이 모두 보이면 정상입니다.

## G 태스크 4: cap-master 인스턴스 시작

**콘솔:** EC2 → 인스턴스 → 인스턴스 시작에서:

| 항목 | 값 |
| --- | --- |
| 태그 | Name=cap-master · Project=capstone · Owner=cap (인스턴스, 볼륨 모두) |
| OS 이미지 | Ubuntu Server 24.04 LTS (HVM) · 64비트(x86) |
| 인스턴스 유형 | m7i-flex.large (2 vCPU / 8 GiB) |
| 키 페어 | 키 페어 없이 계속 진행 |
| VPC · 서브넷 | cap-vpc · cap-subnet-public1-ap-northeast-2a |
| 퍼블릭 IP 자동 할당 | 활성화 |
| 보안 그룹 | 기존 보안 그룹 선택 → cap-k8s-node-sg |
| 기본 IP | 10.20.1.10 |
| 스토리지 | 30 GiB · gp3 |
| IAM 인스턴스 프로파일 | cap-k8s-node-role |
| 메타데이터 버전 | V2 전용(토큰 필수) |
| 메타데이터 응답 홉 제한 | 2 |

! **주의:** `kubeadm init`은 vCPU가 2개 미만이면 `[ERROR NumCPU]`로 중단됩니다.

! **경고:** **홉 제한 2**는 7일차 EBS CSI 드라이버를 위한 설정입니다. 1이면 Pod 안에서 메타데이터를 조회하는 요청이 차단되어 원인을 찾기 어려운 실패를 겪습니다.

💭 퍼블릭 IP는 바깥으로 나가는 통신에만 쓰입니다. 프라이빗 IP를 고정하면 모든 교육생이 같은 주소로 실습하고, 중지 후 재시작해도 클러스터 설정이 유지됩니다.

**확인 (CloudShell, 시작 후 1~2분 뒤):**

```bash
source ~/cap-k8s.env
MASTER_ID=$(aws ec2 describe-instances --filters Name=tag:Name,Values=cap-master Name=instance-state-name,Values=running \
  --query 'Reservations[0].Instances[0].InstanceId' --output text --region $REGION)
echo "export MASTER_ID=$MASTER_ID" >> ~/cap-k8s.env
aws ec2 describe-instances --instance-ids $MASTER_ID \
  --query 'Reservations[0].Instances[0].[InstanceType,Placement.AvailabilityZone,PrivateIpAddress,IamInstanceProfile.Arn,MetadataOptions.HttpPutResponseHopLimit]' \
  --output text --region $REGION
```

**명령어 해석:**

- `describe-instances` — 태그(이름)와 상태(running)로 인스턴스를 찾아 InstanceId를 저장합니다.
- `--instance-ids $MASTER_ID` — 저장한 ID로 하나의 인스턴스만 다시 조회합니다.
- `MetadataOptions.HttpPutResponseHopLimit` — IMDSv2 토큰 응답의 IP 홉 제한 값(여기서는 2)을 확인합니다.

**예상 출력:** 유형 · AZ · IP · 인스턴스 프로파일 · 홉 제한 `2`가 모두 맞으면 정상입니다.

**SSM 등록 확인 (시작 후 2~3분 뒤):**

```bash
aws ssm describe-instance-information \
  --query 'InstanceInformationList[].[InstanceId,PingStatus,PlatformName]' --output table --region $REGION
```

**명령어 해석:**

- `describe-instance-information` — Systems Manager에 등록된 노드와 연결 상태(Online)를 봅니다.

**예상 출력:** `Online`이면 접속 준비가 끝났습니다. 목록이 비면 IAM 프로파일, 에이전트 상태, 퍼블릭 IP, IGW 경로와 아웃바운드 규칙을 확인합니다. 역할 누락이 확인되면 **작업 → 보안 → IAM 역할 수정**에서 지정합니다.
