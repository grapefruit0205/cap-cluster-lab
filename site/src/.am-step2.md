이 페이지는 [① 콘솔에서 인프라 준비](lab02-step1.html)에 이어 cap-master에 모든 노드의 공통 기반을 설치합니다. 이 상태를 AMI로 만들어 워커 노드를 준비합니다.

## A 작업 순서

**시나리오:** 운영팀은 서버마다 설정이 달라지는 일을 막으려 합니다. 마스터에 공통 기반을 한 번 설치하고, 클러스터에 가입하기 전 상태를 AMI로 복제합니다.

| 구성요소 | 역할 | 지금 확인할 것 |
| --- | --- | --- |
| containerd | 컨테이너를 만들고 실행합니다 | 서비스 active, CRI 플러그인 ok |
| kubelet | 각 노드에서 Pod 실행 상태를 관리합니다 | 아직 가입 전이므로 재시작할 수 있습니다 |
| kubeadm | 클러스터 초기화와 노드 가입을 수행합니다 | AMI를 만들기 전 init 금지 |
| kubectl | API Server에 요청하는 관리 도구입니다 | 설치만으로 클러스터가 생기지는 않습니다 |

**실행 경로:** kubelet → CRI → containerd → 컨테이너입니다. cgroup은 CPU·메모리 사용을 관리합니다. kubelet과 containerd가 같은 systemd 방식으로 자원을 관리하도록 맞춥니다.

**주소 계획:** VPC `10.20.0.0/16`, Pod `10.11.0.0/16`, Service `10.96.0.0/12`는 겹치지 않습니다. 서로 다른 용도의 주소를 섞지 않습니다.

```flow TB
(① 완료) -> OS 기본 설정
OS 기본 설정 -> 커널 모듈
커널 모듈 -> containerd 2.x
containerd 2.x -> kubeadm 설치
kubeadm 설치 -> (③ AMI 생성)
```

## B 접속 — 항상 sudo -i 먼저

**왜 하는가:** 기본 셸은 sh라 bash 문법을 못 읽으므로 root bash로 바꿔야 합니다.

**콘솔:** EC2 → 인스턴스 → `cap-master` 선택 → **연결** → **세션 관리자** 탭 → **연결**.

! **주의:** Session Manager 세션은 `ssm-user` 사용자의 `sh`로 시작합니다. `sh`에는 `source`, `<( )` 같은 bash 문법이 없어 `sh: 1: source: not found` 오류가 납니다. 접속하자마자 `sudo -i`를 실행하세요.

```bash
sudo -i
hostname
snap services amazon-ssm-agent
```

**명령어 해석:**

- `sudo -i` — root의 로그인 셸로 완전히 전환합니다. 환경·프롬프트까지 root 기준이 됩니다.
- `hostname` — 현재 호스트 이름을 출력합니다. 어느 노드인지 항상 먼저 확인하세요.
- `snap services` — snap 패키지로 설치된 서비스의 상태를 봅니다.

**예상 출력:** 프롬프트가 `root@ip-10-20-1-10:~#`로 바뀌고, 에이전트는 `enabled / active`입니다.

## C OS 기본 설정 (태스크 5)

**왜 하는가:** 시간 오차와 호스트 이름 불일치는 노드 등록 실패로 이어집니다.

**패키지 · 시간 동기화:**

```bash
apt update
apt install -y vim chrony curl gpg iputils-ping
sed -i 's/^pool /#pool /; s/^server /#server /' /etc/chrony/chrony.conf
echo "server 169.254.169.123 prefer iburst minpoll 4 maxpoll 4" >> /etc/chrony/chrony.conf
systemctl restart chrony
timedatectl set-timezone Asia/Seoul
sleep 5; chronyc sources | grep 169.254
```

**명령어 해석:**

- `apt update` — 저장소의 패키지 목록만 갱신합니다. 설치가 아닙니다.
- `apt install -y` — 설치 질문에 자동으로 yes로 답합니다.
- `sed -i 's/a/b/'` — 파일 안에서 정규식 치환입니다. `-i`는 파일을 직접 수정합니다. 여기서는 기존 NTP 서버 줄을 `#`로 주석 처리합니다.
- `echo "..." >>` — 설정 파일 끝에 Amazon Time Sync(`169.254.169.123`)를 한 줄 추가합니다.
- `timedatectl set-timezone` — 시스템 타임존을 바꿉니다.
- `chronyc sources | grep` — NTP 동기화 소스 목록에서 Amazon 시간 서버만 거릅니다.

**예상 출력:** `169.254.169.123` 앞에 `^*`가 보이면 동기화된 것입니다.

💭 etcd와 인증서 검증은 노드 간 시간 차이에 민감합니다. `169.254.169.123`은 링크 로컬 주소라 인터넷 경로와 무관하게 도달합니다.

**스왑 확인** — Ubuntu 클라우드 AMI는 스왑이 없으므로 `swapoff`가 필요 없습니다:

```bash
swapon --show
free -h | grep -i swap
```

**명령어 해석:**

- `swapon --show` — 활성 스왑 목록을 보여 줍니다. 없으면 출력이 비어 있습니다.
- `free -h` — 메모리 사용량을 사람이 읽는 단위로 봅니다. `grep -i swap`으로 스왑 행만 거릅니다.

**예상 출력:** Swap 행이 `0B`이면 정상입니다.

**호스트 이름 고정** — 이 단계를 건너뛰면 재부팅 후 이름이 되돌아가고 노드가 `NotReady`가 되거나 중복 등록됩니다:

```bash
echo "preserve_hostname: true" > /etc/cloud/cloud.cfg.d/99-preserve-hostname.cfg
hostnamectl set-hostname cap-master
cat <<'EOF2' >> /etc/hosts
10.20.1.10 cap-master
10.20.1.11 cap-node1
10.20.1.12 cap-node2
EOF2
reboot
```

**명령어 해석:**

- `echo "..." > 파일` — 한 줄을 새 파일에 씁니다. `>`는 덮어쓰기, `>>`는 추가입니다.
- `preserve_hostname: true` — cloud-init이 부팅 때마다 호스트 이름을 되돌리는 동작을 막습니다.
- `hostnamectl set-hostname` — 호스트 이름을 영구 변경합니다.
- `/etc/hosts` — 세 노드의 IP-이름 매핑입니다. DNS 없이 이름으로 서로를 찾게 합니다.
- `reboot` — 재부팅합니다. 세션이 끊기는 것이 정상입니다.

**재접속 후 확인:** 세션이 끊기면 1~2분 뒤 다시 접속하고 `sudo -i` 후:

```bash
hostname
```

**예상 출력:** `cap-master` — 되돌아갔다면 `preserve_hostname` 설정부터 다시 하세요.

## D 커널 모듈과 네트워크 파라미터 (태스크 6)

**왜 하는가:** 컨테이너 네트워크와 Pod 통신에 필요한 커널 기능을 켭니다.

```bash
cat <<'EOF2' > /etc/modules-load.d/k8s.conf
overlay
br_netfilter
EOF2
modprobe overlay
modprobe br_netfilter
lsmod | grep -E "^overlay|^br_netfilter"
```

**명령어 해석:**

- `/etc/modules-load.d/k8s.conf` — 부팅 때 자동으로 적재할 커널 모듈 목록입니다.
- `modprobe` — 모듈을 지금 즉시 적재합니다. 재부팅 없이 바로 쓰기 위해서입니다.
- `lsmod | grep -E "..."` — 적재된 모듈 목록에서 두 모듈만 거릅니다. `^`는 줄 시작입니다.

```bash
cat <<'EOF2' > /etc/sysctl.d/k8s.conf
net.bridge.bridge-nf-call-iptables  = 1
net.bridge.bridge-nf-call-ip6tables = 1
net.ipv4.ip_forward                 = 1
EOF2
sysctl --system > /dev/null
sysctl net.bridge.bridge-nf-call-iptables net.ipv4.ip_forward
```

**명령어 해석:**

- `bridge-nf-call-iptables = 1` — 브리지 트래픽도 iptables 처리를 거치게 합니다. 이 교안의 네트워크 사전 설정입니다. 모든 CNI 방식의 공통 필수 조건이라는 뜻은 아닙니다.
- `ip_forward = 1` — 노드가 패킷을 다른 인터페이스로 전달(라우팅)할 수 있게 합니다. Pod 간 통신에 필수입니다.
- `sysctl --system` — 모든 설정 파일을 읽어 커널 파라미터에 적용합니다.

**예상 출력:** 두 모듈이 모두 보이고, 두 sysctl 값이 `= 1`이면 정상입니다.

## E containerd 2.x 설치 (태스크 7)

**왜 하는가:** kubelet은 CRI를 통해 컨테이너 런타임을 쓰므로 2.x를 CRI 활성으로 설치합니다.

! **주의:** Ubuntu 24.04 기본 저장소의 containerd는 1.7.x입니다. Kubernetes v1.36에는 containerd 2.x를 쓰므로 Docker 공식 저장소의 `containerd.io` 패키지를 설치합니다.

**Docker 저장소 추가 + 설치:**

```bash
apt remove -y containerd 2>/dev/null || true
install -m 0755 -d /etc/apt/keyrings
curl -fsSL https://download.docker.com/linux/ubuntu/gpg -o /etc/apt/keyrings/docker.asc
chmod a+r /etc/apt/keyrings/docker.asc
echo "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.asc] https://download.docker.com/linux/ubuntu $(. /etc/os-release && echo $VERSION_CODENAME) stable" \
  > /etc/apt/sources.list.d/docker.list
apt update
apt install -y containerd.io
containerd --version
```

**명령어 해석:**

- `apt remove ... 2>/dev/null || true` — 구버전 제거를 시도하고, 없어서 실패해도 오류 메시지 없이 계속합니다.
- `install -m 0755 -d` — 권한을 지정해 디렉터리를 만듭니다.
- `curl -fsSL` — 오류 시 실패(-f), 조용히(-s), 오류 표시(-S), 리다이렉트 따라가기(-L)입니다.
- `chmod a+r` — 모든 사용자가 키 파일을 읽게 합니다.
- `echo "deb [arch=... signed-by=...]" >` — APT 저장소를 등록합니다. `signed-by`는 해당 저장소의 서명 검증에 사용할 키를 지정합니다.
- `$(dpkg --print-architecture)` — CPU 아키텍처(amd64)를 명령 치환으로 넣습니다.
- `$(. /etc/os-release && echo $VERSION_CODENAME)` — OS 코드명(noble)을 넣습니다.

**예상 출력:** 경로에 `containerd/v2`가 있고 버전이 `2.`로 시작하면 정상입니다.

**기본 설정 생성** — 건너뛰면 안 됩니다. 패키지 기본 설정에는 `disabled_plugins = ["cri"]`가 있습니다:

```bash
mkdir -p /etc/containerd
containerd config default > /etc/containerd/config.toml
grep -n "^version" /etc/containerd/config.toml
```

**명령어 해석:**

- `containerd config default` — 표준적인 기본 설정을 출력으로 내보냅니다. `>`로 파일에 저장합니다.
- `grep -n "^version"` — 줄 번호와 함께 버전 키를 확인합니다.

**예상 출력:** `version`이 **3 또는 4**면 containerd 2.x 형식입니다.

**systemd cgroup 드라이버** — 키가 있으면 값만 바꾸고, 없으면 추가합니다:

```bash
if grep -q "SystemdCgroup" /etc/containerd/config.toml; then
  sed -i 's/SystemdCgroup = false/SystemdCgroup = true/' /etc/containerd/config.toml
else
  sed -i "/runtimes.runc.options\]/a SystemdCgroup = true" /etc/containerd/config.toml
fi
grep -n "SystemdCgroup" /etc/containerd/config.toml
```

**명령어 해석:**

- `grep -q` — 출력 없이 존재만 확인합니다. 결과로 if 분기를 합니다.
- `sed -i "/패턴/a 내용"` — 패턴이 있는 줄 **뒤에** 내용을 추가합니다(`a` = append).
- kubelet과 containerd의 cgroup 드라이버를 같은 **systemd**로 맞추는 설정입니다.

! **경고:** `SystemdCgroup = true`가 **정확히 한 줄**이어야 합니다. 두 줄이 되면 TOML 중복 키로 containerd가 시작되지 않습니다. 두 줄이 보이면 기본 설정 생성부터 다시 하세요.

**레지스트리 미러 (config_path 방식):**

```bash
sed -i "s|config_path = ''|config_path = '/etc/containerd/certs.d'|" /etc/containerd/config.toml
mkdir -p /etc/containerd/certs.d/docker.io
cat <<'EOF2' > /etc/containerd/certs.d/docker.io/hosts.toml
server = "https://docker.io"

[host."https://mirror.gcr.io"]
  capabilities = ["pull", "resolve"]

[host."https://registry-1.docker.io"]
  capabilities = ["pull", "resolve"]
EOF2
```

**명령어 해석:**

- `config_path = '/etc/containerd/certs.d'` — 이 디렉터리에서 레지스트리별 설정을 읽게 합니다. containerd 2.x 방식입니다.
- `docker.io/hosts.toml` — Docker Hub 요청에 적용되는 미러 설정입니다.
- `[host."URL"]` — 미러 후보입니다. 여러 개면 위에서부터 시도합니다.
- `capabilities = ["pull", "resolve"]` — 이 미러로 이미지 내려받기와 이름 해석만 한다는 뜻입니다.

**검증 + 재시작:**

```bash
containerd -c /etc/containerd/config.toml config dump > /dev/null && echo "config OK"
systemctl restart containerd
systemctl is-active containerd
ctr plugin ls | grep -i "cri.v1"
```

**명령어 해석:**

- `config dump > /dev/null` — 설정을 문법 검증 겸 출력해 버립니다. 실패하면 `config OK`가 안 찍힙니다.
- `systemctl is-active` — 서비스 상태를 한 단어로 출력합니다.
- `ctr plugin ls` — containerd 플러그인 목록입니다. CRI(`cri.v1`)가 `ok`여야 쿠버네티스가 런타임을 쓸 수 있습니다.

**예상 출력:** `config OK`, `active`, CRI 줄의 마지막 열이 모두 `ok`이면 정상입니다.

## F kubeadm · kubelet · kubectl 설치 (태스크 8)

**왜 하는가:** 클러스터를 만들고 관리할 도구를 같은 버전으로 고정합니다.

**v1.36 저장소 등록:**

```bash
curl -fsSL https://pkgs.k8s.io/core:/stable:/v1.36/deb/Release.key | gpg --dearmor -o /etc/apt/keyrings/kubernetes-apt-keyring.gpg
echo 'deb [signed-by=/etc/apt/keyrings/kubernetes-apt-keyring.gpg] https://pkgs.k8s.io/core:/stable:/v1.36/deb/ /' \
  > /etc/apt/sources.list.d/kubernetes.list
apt update
apt-cache madison kubeadm | head -3
```

**명령어 해석:**

- `gpg --dearmor` — 텍스트 키를 apt가 쓰는 바이너리 키링으로 변환합니다.
- `sources.list.d/kubernetes.list` — 쿠버네티스 v1.36 패키지 저장소를 등록합니다.
- `apt-cache madison` — 저장소에서 설치 가능한 버전 나열입니다. `head -3`은 위 3줄만 봅니다.

**최신 버전 설치 + 버전 고정** — 세 패키지는 **반드시 같은 버전**입니다:

```bash
K8S_VER=$(apt-cache madison kubeadm | awk 'NR==1{print $3}')
echo "설치 버전: $K8S_VER"
apt install -y kubelet=$K8S_VER kubeadm=$K8S_VER kubectl=$K8S_VER cri-tools
apt-mark hold kubelet kubeadm kubectl
systemctl enable --now kubelet
kubeadm version -o short
crictl --version
```

**명령어 해석:**

- `awk 'NR==1{print $3}'` — 첫 줄의 세 번째 필드(최신 버전)를 뽑아 변수에 저장합니다.
- `패키지=버전` — 특정 버전을 지정해 설치합니다. 세 패키지를 같은 버전으로 맞춥니다.
- `apt-mark hold` — 버전을 고정해 `apt upgrade` 때 바뀌지 않게 합니다.
- `systemctl enable --now` — 부팅 시 자동 시작 등록 + 지금 즉시 시작입니다.

! **주의:** `apt-mark hold`를 빠뜨리면 `apt upgrade` 때 버전이 어긋날 수 있습니다. 이 시점에 kubelet은 설정이 없어 재시작을 반복하며, `kubeadm init` 전까지는 정상입니다.

**pause 이미지 맞추기:**

```bash
PAUSE=$(kubeadm config images list 2>/dev/null | grep pause)
echo "$PAUSE"
sed -i "/pinned_images/,+3 s|sandbox = .*|sandbox = '${PAUSE}'|" /etc/containerd/config.toml
containerd -c /etc/containerd/config.toml config dump > /dev/null && systemctl restart containerd
grep -A3 "pinned_images" /etc/containerd/config.toml | grep sandbox
```

**명령어 해석:**

- `kubeadm config images list` — 이 클러스터가 쓸 이미지 목록입니다. `grep pause`로 pause 이미지 버전만 거릅니다.
- `sed -i "/pinned_images/,+3 s|...|...|"` — `pinned_images` 줄부터 3줄 범위 안에서 `sandbox` 값을 kubeadm이 쓰는 버전으로 바꿉니다.
- `grep -A3` — 매칭 줄과 그 뒤 3줄까지 함께 봅니다. pause 이미지가 일치하는지 확인합니다.

**예상 출력:** 두 줄의 pause 이미지 이름이 같으면 정상입니다.
